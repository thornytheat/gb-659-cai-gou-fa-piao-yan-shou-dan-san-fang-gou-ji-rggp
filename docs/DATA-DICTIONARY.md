# 数据字典

- run_id：规则版本与输入 SHA-256 前 12 位组成的稳定批次标识。
- line_no：从 1 开始的物理来源行号，不因隔离或排序改变；CSV 数据行从 2 开始（第 1 行是表头）。
- business_key：本项目声明的业务唯一键（货号|税率），始终按字符串存储。
- reason_code：隔离原因的稳定英文编码。
- accepted：进入业务计算的记录数。
- quarantined：保留证据但不参与业务计算的记录数。
- 数值：金额、税额、用量和权重使用 Decimal；对外序列化为字符串，金额统一到分。
- 时间：存储为带偏移的 ISO 8601，分桶使用半开区间。
- 空值：缺失键、空串和业务哨兵分别记录。
- 幂等：完整输入字节与规则版本相同则复用 run_id，不新增结果。

## 匹配与批次

- approved：已核准配对，元素为 `{invoice_id, receipt_ids}`。已核准配对稳定优先，
  但默认策略 `settle` 允许在旧票存在等额替代验收单时挪配，使新票也能结算。
- policy：`settle`（默认，最大化结算张数，其次最大化原样保留的核准配对）或
  `stable`（核准配对是硬约束，新票挂起）。
- pairings[].approval：`KEPT` 原样保留 / `MOVED` 挪配到另一组等额验收单 /
  `NEW` 新配对。
- pending[].reason_code：发票未结算的原因。
  - `RECEIPT_HELD_BY_APPROVED`：唯一可行组合被已核准配对占用，且旧票无等额替代组。
  - `RECEIPT_OCCUPIED`：唯一可行组合被其他发票占用。
  - `NO_EQUAL_SUBSET`：组内没有金额落在容差内的验收单组合。
  - `NO_RECEIPT`：同货号同税率组内没有可用验收单。
  - `APPROVED_RECEIPT_MISSING`：核准配对引用的验收单本次未采信。
- 验收单占用：同一 `run_id` 内一张验收单最多归属一张发票，`receipt_usage` 的
  `rows == distinct` 才视为互斥。
- 差异批次对账：验收单基数 = 已配对实际金额 + 未开票验收金额；发票基数 =
  已配对实际金额 + 待处理发票金额。配对行按验收单实际金额合计与发票金额比较。
- 采信边界：只有 M1 `accepted` 行（且 M2 映射成功）进入匹配，隔离行只保留证据。
